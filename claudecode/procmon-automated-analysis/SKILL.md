# skill title: Procmon 自动化分析流程

## 版本信息

1.0 实现关于进程关系之间的迭代分析。

## 配置参数 (开始分析前，向用户进行询问)

注意：所有要执行的命令参数，路径中不能使用 `/` 而是要使用 windows 平台的 `\\` 

0. **ProcessMonitor监控工具路径**：监控工具`Procmon64.exe`所在位置。
   - 验证：检查文件是否存在
   - 示例：`C:\Users\user\Desktop\Procmon64.exe`

1. **工作目录创建**：你需要在当前目录创建以被监控内容为名称的目录，并将报告以及其他输出产物保存到该目录中

2. **要被监控的可执行文件路径**：目标可执行文件的完整路径
   - 验证：检查文件是否存在
   - 示例：`C:\Users\user\Desktop\suspicious.exe`

3. **捕获时长**：单次监控秒数（每次询问）
   - 范围：通常 10-300 秒
   - 复杂程序需要更长时间

4. **进程过滤器**：用于过滤的进程名（从可执行文件名自动检测）
   - 关系类型：`contains`（默认）
   - 可根据需要覆盖

5. **分析深度选择**：仅分析当前进程行为，或分析当前进程以及其可疑的后辈进程的行为。
    - 选择 0：仅分析当前进程。
    - 选择 1：分析当前进程以及该进程产生可疑子进程和子进程产生的可疑子进程，直到不再有新的可疑后辈进程产生。

6. **报告生成格式**：使用markdown格式，使用简体中文生成报告，参考下面的"报告模板". 每分析完一个进程就进行记录，之后继续向后追加。

报告模板：

```

命令行：aaa.exe xxxx xxxx -xxx xxx

## 进程&线程行为：

 - 所有的进程创建
 - 可疑的线程创建
 - 可疑的模块加载

## 网络行为：
 - 所有网络事件
 - 高频网络行为
 - 可疑的网络事件
 - 可疑的本地网络事件
 
## 注册表事件：
 - 敏感的注册表读取操作
 - 可疑的注册表写入/删除操作

## 文件事件：
 - 可疑的文件写入事件
 - 可疑的文件读取事件

        - 如果是利用可疑的powershell或者cmd执行了什么陌生进程或者潜在的内存马，那么就就属于需要继续分析的后续行为。

2. 你应该从当前进程的收集结果中，寻找 ProcessCreate 事件来发现子进程，而不是通过命令查询的方式。
```

## MCP 工具调用序列

### 步骤 1：生成配置

当你获取到用户输入的配置信息后，需要使用MCP中下面的工具来生成 ProcMon 配置文件的前体。 

```
mcp__ProcMon_MCP__generate_capture_config(
    process_filter="<进程名>",
    relation="contains",
    action="include"
)
```

或直接使用 `generate_pmc_file` 创建 PMC 文件：

```
mcp__ProcMon_MCP__generate_pmc_file(
    process_filter="<进程名>",
    output_path="<时间戳>_<过滤器>.pmc"
)
```

### 步骤 2：启动捕获

你需要使用下面的MCP工具，将构造好的PMC配置文件导入到procmon进行监控

```
mcp__ProcMon_MCP__start_procmon_capture(
    pmc_file_path="<pmc路径>",
    runtime_seconds=<时长>,
    procmon_path="C:\Users\user\Desktop\Procmon64.exe",
    wait_for_completion=False
)
```

### 步骤 3：启动目标进程

启动捕获后等待 2 秒，然后：

```
mcp__ProcMon_MCP__launch_process(
    executable_path="<目标exe>",
    wait_for_completion=False
)
```

### 步骤 4：等待完成

休眠 `时长 - 3` 秒，然后检查 PML 文件。

### 步骤 5：转换并加载日志

Procmon 生成 `.PML`（二进制格式）。转换格式为 XML：

```
# 命令行（外部执行）: 注意使用正确的路径
Procmon64.exe /OpenLog "<pml路径>" /SaveAs "<xml路径>"
```

然后加载 XML：

```
mcp__ProcMon_MCP__load_file(
    file_path="<xml路径>"
)
```

### 步骤 6：分析事件

关键分析查询：

**内存安全分析**

callstack分析：
- callstack中往往会展示出异常的栈帧信息，这表示可能出现了shellcode执行或者是出现可疑的模块。
- 高级的恶意软件往往会对callstack进行spoof，混淆，但尽管进行了混淆，依旧会展现出和正常callstack不同的地方。

异常的 模块 加载模式：
- 不可信的进程加载了PowerShell或者是其他脚本引擎模块，这表明可能存在可疑的内存代码执行。
- 异常的加载模式：比如加载了多个exe文件，这在进程执行过程中是不正常的行为。


## 常见问题处理

| 问题 | 解决方案 |
|-------|----------|
| Procmon 未找到 | 验证 `PROCMON_PATH` 是否正确 |
| PMC 生成失败 | 安装 `procmon_parser` 库 |
| PML 文件未创建 | 检查 Procmon 权限，以管理员运行 |
| 未捕获到事件 | 验证进程过滤器与可执行文件匹配 |
| XML 导出失败 | 使用 `/SaveAs` 并提供完整路径 |

过程中遇到任何问题，都可以随时向用户进行询问，目的是：
- 使用户知情
- 由用户提供解决方案决策


## 前置条件

1. **Procmon** 已安装在配置路径
2. **procmon_parser** 库可用
3. **psutil** 库用于进程管理
4. **管理员权限** 用于 Procmon 捕获
